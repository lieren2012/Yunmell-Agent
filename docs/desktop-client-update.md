# 云迈桌面客户端内更新

## 现状与启用

1.0.9 及以前的桌面壳没有 EXE 更新器；内置 Python 运行时的在线更新不能替换桌面程序。因此旧安装需要先安装一次带更新器的 1.0.10 测试包。此后通过客户端内更新，不使用 git pull。

启动自动检查云迈 GitHub Releases。手动检查入口：托盘设置 → 检查客户端更新，或应用设置 → 云迈自研更新 → 客户端内更新。更新窗口独立于本机工作台，即使工作台尚未启动也可检查更新；恢复入口为 `Yunmell-Agent.exe --client-updates`。

默认只检查稳定版。测试 b1 → b2 时，在客户端更新窗口勾选“包含测试版”。

## 下载和安装

1. 从已配置仓库读取 Releases，过滤草稿、测试版和旧版本。
2. 只匹配当前系统与 CPU 架构的 `Yunmell-Agent-desktop-<平台>-<版本>` 资产。
3. 校验仓库、版本、文件名和 HTTPS 来源；下载重定向仅允许 GitHub 官方资产域名。
4. 下载到本机 `OCTOP_HOME/updates`，显示字节进度。强制校验 GitHub API 的 SHA-256 digest；缺失时校验同一 Release 的 `.sha256` 文件。缺少校验信息或校验失败禁止安装。
5. 下载完成后等待用户保存工作并确认。安装前重新校验文件，保留旧程序备份，然后退出本机客户端。
6. Windows 运行 NSIS 安装器并验证新 EXE 自报版本；失败恢复旧 EXE。独立监视进程用原用户权限重新启动客户端，管理服务器不会被重启。
7. macOS 使用 DMG 中的应用包，Linux 使用已校验的 tar.gz。没有安装目录写入权限时停止更新并保留当前程序。

客户端更新结果保存到 `OCTOP_HOME/updates/last-install.json`。数据库、会话、文件、配置和企业地址位于 `OCTOP_HOME`，不属于安装包覆盖范围。下一次启动升级内置运行时前，沿用 SQLite 备份与原子替换机制。

## 更新源

第一阶段仅实现 GitHub Releases。默认 `lieren2012/Yunmell-Agent`；管理员可通过桌面设置文件的 `updateRepository` 或环境变量 `YUNMELL_UPDATE_REPO=owner/repository` 指定经过信任的 GitHub 仓库。选定源后只接受该仓库的资产和校验文件。自有服务器发布清单协议属于后续阶段，当前不支持任意 URL 作为安装源。

## 两条更新线

官方 Octop 更新只展示已集成的官方基线、官方最新版本及同步来源。桌面旧 `/api/update/upgrade` 安装入口被禁止，防止 PyPI 官方包覆盖云迈企业代码。

云迈桌面壳版本独立于 Python 运行时和企业管理服务器版本。已安装客户端仅安装云迈 Release 中的完整平台客户端；服务器仍按自身的部署流程升级。

## 验证

自动测试覆盖版本选择、架构匹配、测试版过滤、错误来源、缺少校验、下载损坏、安装前文件变更、用户确认和失败恢复旧 EXE。真实安装测试要使用独立安装目录和 `OCTOP_HOME`，验证 b1 内发现 b2、下载、确认安装、重新启动、当前版本变为 b2，以及本地文件/SQLite/企业连接配置保留。CI 构建或导入检查不能代替此安装测试。
