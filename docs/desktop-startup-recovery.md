# 桌面端企业管理连接与启动恢复

## 原因和修复

1.0.10b6 的管理端检查使用 Go 默认 HTTP 客户端。存在 `HTTP_PROXY/HTTPS_PROXY` 且 `NO_PROXY` 未包含内网地址时，请求可能被交给代理。代理返回 502 后，旧界面统一报告“服务尚未就绪”，不能证明管理服务器故障。

1.0.10b9 的企业内网/本机健康检查独立直连；模型请求和 GitHub 更新下载保留原代理策略。健康检查设置单请求和总体超时、禁止重定向，必须是 HTTP 200 且有效 JSON。管理端要求 `ok=true` 和 `db=true`；本机运行时允许尚在初始化向导阶段的 `db=false`，登录和初始化仍受原有认证界面保护。

管理端与本机运行时分别标记检查结果、地址、连接路径和 HTTP 状态。桌面工作台只打开本机地址，`OCTOP_DESKTOP_URL` 只允许本机开发地址。已有本机端口服务不属于当前客户端时，不强制覆盖它，提示关闭旧云迈进程后重试。

## 无损恢复

- 从客户端更新窗口升级到 b9；旧启动页面卡住时，可用已安装 EXE 的 `--client-updates` 打开独立更新窗口。
- 测试包需要勾选“包含测试版”。新安装默认填写 `https://agent-oc.yun.cab`；地址可修改保存，不将企业管理地址作为本机工作台地址。
- 若提示本机 8088 已有旧运行时，先正常退出旧客户端。不要删除 `OCTOP_HOME`、数据库、portable 目录或企业连接配置。
- 启动页提供“重试启动”“连接设置”“客户端更新”。检查失败后可以直接重试。
- 安装与运行时升级前保留 SQLite 备份；故障处理应先核对进程路径，仅处理当前云迈项目的进程。

## 诊断

运行 `Yunmell-Agent.exe --startup-diagnose` 可输出角色、脱敏后的目标地址、HTTP 状态和 JSON 就绪判定。对比旧默认代理请求的 HTTP 状态，区分代理问题与管理端问题。

最近一次启动结果保存在 `OCTOP_HOME/desktop-startup.json`，默认 Windows 路径为 `C:\Users\<用户>\.octop\desktop-startup.json`。文件不记录代理凭据、登录密码、令牌或响应正文。

## 连接设置与重试验收

启动页的连接设置使用独立窗口，不依赖托盘弹窗。地址保存后点击重试，客户端会重新读取已保存设置；设置文件损坏时显示错误并保留原有内存设置。

2026-10-12 在隔离数据目录实际验证：先使用不可达地址得到限时诊断，在连接窗口改为企业管理地址，保存并关闭后点击重试。管理端 HTTP 200、直连；本机 16689 HTTP 200，打开本机初始化向导。未提交登录或注册，未改动管理服务器。
